# LLM Track Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make phi-scrub usable inside LLM pipelines: reversible redaction, healthcare identifier detectors, and a stdio MCP server.

**Architecture:** Three additive layers on the existing regex engine. Task 1 adds numbered tokens plus a token map that the caller keeps, and a `restore` function that inverts them. Task 2 moves the patterns into a detector table that supports check-digit validators and context-anchored capture groups, then adds four detectors. Task 3 wraps `detect`, `redact_reversible`, and `restore` as MCP tools behind an opt-in cargo feature.

**Tech Stack:** Rust 2021, `regex`, `serde`, PyO3 0.29 + maturin, `proptest` (dev), `rmcp` + `tokio` + `schemars` (feature `mcp` only).

**Spec:** The Design section of this file, approved by Jeremy on 2026-11-13.

## Design (approved 2026-11-13)

- **Why:** an LLM workflow needs the original values back after the model replies. Fixed tokens such as `[SSN]` cannot be mapped back, the engine detects three identifier types, and there is no MCP entry point.
- **Fit with the roadmap:** this track rides in the 0.2.0 line next to the Phase 1 detector list (names, dates/DOB, MRN, address, `wasm`, npm). Task 2's detector table is the plumbing those detectors need, and its MRN detector closes the Phase 1 MRN item. The `wasm` and npm tasks are untouched.
- **Approaches considered:**
  1. *Stateless token map returned to the caller (chosen).* The library stores nothing, so there is no PHI at rest and nothing to secure or expire.
  2. *Server-side session store keyed by an ID.* Simpler calls for the client, but the library would hold PHI and need a lifetime policy.
  3. *Hashed tokens (`[SSN_a1b2c3]`).* Stable across calls, but a hash of a low-entropy value such as an SSN can be brute-forced.
- **MCP server language:** Rust, on the official `rmcp` SDK, as a `phi-scrub mcp` subcommand behind an `mcp` feature. One binary serves the CLI and the MCP server. A Python wrapper was the alternative; it would add a second runtime to a Rust-first project.

## Global Constraints

- No `unwrap()` or `expect()` outside `static` pattern init and tests.
- Every public item has a doc comment (`#![deny(missing_docs)]` is on).
- Library errors use `thiserror`; the binary uses `anyhow`.
- A new dependency needs a one-line justification in its commit message.
- The public API in `src/lib.rs` changes additively only. `Scrubber`, `Finding`, `Category`, and `Error` keep their shape, and `redact()` output does not change for existing categories.
- No files outside the crate root.
- The token map goes back to the caller. The library stores nothing.
- The `mcp` feature stays out of `default`, so a future `wasm` build is unaffected.
- No version bump, no tag, no publish. `__version__` stays `0.1.0`.
- Definition of done for every task, in order:
  ```bash
  cargo fmt --check
  cargo clippy --all-targets -- -D warnings
  cargo test
  cargo doc --no-deps
  uv sync && uv run maturin develop --release && uv run pytest python/tests -q
  ```

## Review Focus

1. Multi-byte text around a match: the round trip must stay byte-exact (Task 1, `round_trip_with_multibyte_text`).
2. Input that already contains token-shaped text: that token is never issued and never restored (Task 1, `token_already_in_input_is_never_issued`, `restore_is_single_pass`).
3. A ten-digit number that is both phone-shaped and a valid NPI: one finding, NPI wins; an invalid one stays PHONE (Task 2, `valid_npi_outranks_phone_on_same_span`, `ten_digits_failing_luhn_are_not_npi`).
4. An "MRN" label followed by a word instead of a number: no finding (Task 2, `mrn_label_without_digits_is_ignored`).
5. An MCP `redact` call with empty text or no PHI: the text comes back unchanged with an empty map, not an error (Task 3, `redact_with_no_phi_returns_empty_map`).

**Interfaces:**
- Consumes: `Scrubber::detect`, `Category::token` (existing).
- Produces:
  ```rust
  /// JSON shape: {"[SSN_1]": "123-45-6789"}
  pub struct TokenMap(BTreeMap<String, String>);
  impl TokenMap {
      pub fn new() -> Self;
      pub fn get(&self, token: &str) -> Option<&str>;
      pub fn len(&self) -> usize;
      pub fn is_empty(&self) -> bool;
      pub fn iter(&self) -> impl Iterator<Item = (&str, &str)>;
  }
  impl FromIterator<(String, String)> for TokenMap;
  pub struct Redaction { pub text: String, pub map: TokenMap }
  impl Scrubber { pub fn redact_reversible(&self, text: &str) -> Redaction; }
  pub fn restore(text: &str, map: &TokenMap) -> String;
  ```
  Python: `Scrubber.redact_reversible(text) -> tuple[str, dict[str, str]]` and `phi_scrub.restore(text, token_map) -> str`.
- Token rules, which Tasks 2 and 3 rely on:
  - Shape is `[<LABEL>_<n>]`. `LABEL` is the category token without brackets (`SSN`, `PHONE`, `EMAIL`). `n` starts at 1 per category and follows first appearance.
  - The same category and value always get the same token within one call.
  - A token string that already occurs in the input is never issued.
  - `restore` makes one left-to-right pass. It replaces only substrings shaped like `\[[A-Z]+_[0-9]+\]` that are keys in the map, and leaves everything else alone.

### Task 2: Checksum and context detectors

**Files:**

**Interfaces:**
- Consumes: Task 1's token rule. `LABEL` comes from `Category::token()`, so new categories get numbered tokens with no extra code.
- Produces: `Category::{Npi, Dea, Mbi, Mrn}` with tokens `[NPI]`, `[DEA]`, `[MBI]`, `[MRN]`; serde names `Npi`, `Dea`, `Mbi`, `Mrn`; Python category strings `npi`, `dea`, `mbi`, `mrn`.
- Internal, in `src/detectors.rs`:
  ```rust
  pub(crate) struct Detector {
      pub category: Category,
      pub regex: Regex,
      pub group: usize,                       // capture group reported as the finding
      pub validate: Option<fn(&str) -> bool>, // runs on the reported text
  }
  pub(crate) static DETECTORS: LazyLock<Vec<Detector>>;
  pub(crate) fn npi_checksum(digits: &str) -> bool;
  pub(crate) fn dea_checksum(candidate: &str) -> bool;
  ```
- Detection rules:
  - **NPI:** `\b[12]\d{9}\b`, then Luhn over `80840` followed by the ten digits.
  - **DEA:** `\b[A-Za-z][A-Za-z9]\d{7}\b`, then `(d1 + d3 + d5 + 2 * (d2 + d4 + d6)) % 10 == d7`.
  - **MBI:** eleven characters, uppercase, optional dashes in the 4-3-4 layout: `\b[1-9]L[L0-9]\d-?L[L0-9]\d-?LL\d\d\b` where `L` is `[AC-HJKMNP-RT-Y]` (no S, L, O, I, B, Z).
  - **MRN:** label required. `(?i)\b(?:MRN|medical record (?:number|no\.?|#))\s*[:#]?\s*([A-Z0-9][A-Z0-9-]{4,14})\b`, reporting group 1, and only when it contains a digit.
- `detect` returns findings that never overlap. The earliest start wins, then the longest, and for an identical span the earlier detector in the table wins. Table order: SSN, MRN, NPI, DEA, MBI, PHONE, EMAIL. A labeled MRN therefore beats a checksum or phone match of the same span, and a valid NPI beats a phone match.

**Interfaces:**
- Consumes: `Scrubber::detect`, `Scrubber::redact_reversible`, `restore`, `TokenMap` (Task 1); the categories from Task 2.
- Produces: `phi-scrub mcp`, compiled only with `--features mcp`. With no subcommand the binary keeps reading stdin and writing redacted text. MCP tools:

  | Tool | Arguments | Structured result |
  |---|---|---|
  | `detect` | `{ "text": string }` | `{ "findings": [{ "start", "end", "category" }] }` |
  | `redact` | `{ "text": string }` | `{ "text": string, "token_map": { token: value } }` |
  | `restore` | `{ "text": string, "token_map": { token: value } }` | `{ "text": string }` |

- Server name `phi-scrub`, version from `CARGO_PKG_VERSION`. stdout carries protocol frames only; diagnostics go to stderr.
- Pin `rmcp` to the current release at implementation time, with features `transport-io` and `schemars`. If `rmcp` needs a newer Rust than the manifest's `rust-version = "1.80"`, raise `rust-version` to that floor and record the ruling.
